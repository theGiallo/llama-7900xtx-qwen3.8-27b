# E1/E2 — ROCmFP4 MMVQ warps + aligned loads (2026-09-25, gfx1100)

Branch HEAD before edits: `5efe75c30`. All perf = `test-backend-ops perf -b ROCm0 -o MUL_MAT`
at FFN shapes (m/k in {17408,5120}, n=1..8), us/run. Runs repeated 3x, median reported.

## E1 — warp count (calc_nwarps, mmvq.cu)

Tried ROCmFP4 types in the RDNA3_0 `ncols_dst==1` whitelist at 8 warps, and n=2..8 at
8 warps:

- **n=1, k=5120 strongly regresses at 8 warps** (+42..+71 %): k=5120 is only 160 quantized
  blocks, so a 512-thread block leaves threads 160-511 idle. `should_use_small_k()` would
  pack more rows per block to compensate but is **disabled for RDNA** (`GGML_CUDA_CC_IS_RDNA → false`).
- **n>=2, k=5120 also regresses (+60 %)** for the same reason (RDNA `calc_rows_per_block` is
  pinned to 1).
- n=1, k=17408 (544 blocks) is ~flat (+10 %).
- Run-to-run noise at FFN shapes is ±5-8 %, so everything within that band is noise.

**E1 conclusion: warps are not the lever for ROCmFP4 MMVQ.** 1 warp already splits the K loop
optimally for these shapes; ROCmFP4 @ 1 warp already beats Q4_0 @ 8 warps at n=1 (E0).
Reverted the `calc_nwarps` edit; no kernel change from E1.

## E2 — aligned 16-byte qs loads (vecdotq.cuh)

`block_rocmfp4`/`block_rocmfp4_fast` are packed at 18/17-byte strides, so the four
`get_int_b4` (4-byte `int*`) loads per block are unaligned. Replaced with one
`memcpy`-wide load of the whole `qs` field:

- `q4_0_rocmfp4` (VDR=4, iqs==0): single `uint4` load, register-promotable.
- `q4_0_rocmfp4_fast` (VDR=2, iqs∈{0,2}): single 8-byte load at `qs+4*iqs`, extract two words
  from the register value. (A first attempt indexed the `uint4` at the runtime `iqs` and spilled to
  local memory: +140..+460 % — avoided by loading the 8 bytes the thread actually uses.)

### Results (median of 3, vs E0 baseline)

| type | shape | n=1 | n=2 | n=4 | n=8 |
|------|-------|-----|-----|-----|-----|
| q4_0_rocmfp4 | 17408x5120 | **-8.4 %** | -4.6 % | -3.4 % | -4.0 % |
| q4_0_rocmfp4 | 5120x17408 | **-6.8 %** | -5.3 % | -3.5 % | -3.9 % |
| q4_0_rocmfp4_fast | 17408x5120 | **-8.6 %** | -4.8 % | -2.7 % | -6.0 % |
| q4_0_rocmfp4_fast | 5120x17408 | **-7.4 %** | -5.4 % | -3.6 % | -5.0 % |

Consistent 3-8 % faster everywhere; spread within a run ~0.2-3.4 %, smaller than the gain.
`test-backend-ops -p "rocmfp4"` passes 2/2 backends (42/42 cases) after the change.

### Reading

The 4->1 wide load saves ~3 unaligned 4-byte global loads per 32-value block; on the decode
(FFN n=1, ~35 us/matmul) that's worth ~2.5 us per up/down matmul. Modest but real and free.
The `iqs`-indexed `uint4` spill trap is worth remembering for future kernels on RDNA3.
